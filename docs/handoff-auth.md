## Implemented

- Server Google authorization-code flow using official `google-auth-library`: exact canonical callback, PKCE S256, random browser-bound state and nonce, ten-minute state expiry and atomic one-time consumption.
- OAuth origin validation requires the exact canonical raw `Host`. Normal requests require the canonical URL origin; only `DENO_DEPLOY=true` permits Next's reconstructed `0.0.0.0` listener URL at the configured `PORT` (default `8000`). Outside deployment, an explicitly configured `127.0.0.1` or `[::1]` origin also accepts NextURL's `localhost` normalization with the same protocol and effective port; the incoming Host must still match the configured loopback IP exactly. Forwarding headers cannot establish host identity, and linking still requires the canonical browser `Origin`. These checks address standalone reconstruction without changing the registered callback.
- ID-token signature verification plus issuer, audience, authorized party, expiration/issued-at freshness, subject, nonce, and verified-email checks. Google subject is the account identity; an email match never auto-links an existing password account. Token exchange and verification certificate fetch have bounded timeouts.
- Explicit linking requires the account password, a current session, matching email, and unchanged authentication version. Both session and user are checked atomically when committing a link.
- Google-only deletion requires explicit confirmation and recent Google proof bound to the initiating local session. Wrong identity/session and concurrent logout/user changes cannot grant deletion proof.
- Opaque, hashed, HttpOnly seven-day sessions. Password change/recovery rotates recovery codes, increments authentication version and revokes older sessions without removing a concurrent login using the new version. User/profile/password/delete commits check authenticated session and user snapshots.
- Owner sessions store `createdAt` and enforce an explicit one-hour lifetime, including rejection of future or malformed timestamps. Order-status commits atomically check the owner-session snapshot so concurrent logout or session replacement cannot authorize a write. Explicit expiry is necessary because KV expiry can remove records after their logical expiration time.
- Passwords preserve intentional whitespace; malformed stored hashes fail closed. Unknown/Google-only password login uses a precomputed dummy hash to perform the same single password derivation as password accounts.
- Account deletion records a tombstone bound to the initiating session, denies ordinary account access, and permits idempotent cleanup retry in that session. User/email/Google indexes and initiating session are removed atomically after cleanup succeeds. Remaining invalid sessions are removed or expire. The account page shows a pending-deletion retry view after reload; Google proof can be renewed while pending without restoring ordinary access.
- Account UI includes loading/retry, session-expiry recovery, Google availability/cancellation/linking, password rotation, one-time recovery-code copying, data export, billing panel, orders, footer, and account metadata with noindex.

Root supplied `lib/http-security.ts`; OAuth start/link now use its configured-proxy rate limit, exact-origin validation, and streaming byte-limited JSON object reader. Spoofed forwarding headers cannot buy extra attempts unless deployment explicitly trusts an ingress-overwritten header.

## Operations and limits

Set app-specific `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `APP_URL`; register exactly `${APP_URL}/api/auth/google/callback`. `/api/auth/config` remains unavailable when configuration is absent or invalid. Secrets are server-only and not returned to clients; OAuth access/refresh tokens are not retained.

At rollout, existing owner sessions stored as boolean values are rejected. Owners must sign in again to receive a timestamped session. Customer sessions are unaffected.

If the initiating session expires or its cookie is cleared while a deletion is pending, an operator must finish cleanup for the tombstoned account. Tombstones deliberately deny new sessions and email reuse until cleanup finishes. This fail-closed limitation applies to a persistent cleanup failure or abandoned retry. Local billing cleanup does not cancel RevenueCat subscriptions or delete provider payment records; the UI tells users to manage subscriptions before account deletion.

Official protocol references: [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect) and [Google OAuth for web servers](https://developers.google.com/identity/protocols/oauth2/web-server). Relevant installed Next.js guides for route handlers, cookies, metadata, authentication and `useRouter` were read before edits.
